Binary register

The register the Zeckendorf register is measured against: digits weighing 1, 2, 4, 8, …, every pattern of 0s and 1s a valid number, and one rule, the carry. phi_prune.register models it as the kind "binary", with the same functions as the Zeckendorf register.

  • One rule.The carry fires on a digit of 2 or more: d[k] − 2, d[k+1] + 1, since 2 · 2k = 2k+1. It only moves up.
  • Normal form.Every digit 0 or 1. Each value has one normal form, so the carries reach it in any order, as the Zeckendorf register's rules do.
  • No check.Every pattern is a valid number, so flip_detected is false for every single-bit flip, where a Zeckendorf register catches the flips that leave two adjacent 1s.

The component below works on an 8-bit register drawn most significant bit first. Arithmetic adds two numbers digit by digit and then carries in passes from the least significant end, each pass carrying every digit of 2 or more it meets into the next place up, until no digit is 2 or more; it also subtracts with a borrow, which phi_prune.register does not model, since both of its registers hold non-negative values only. Tree draws the calls of a recursive to_bin(n): each call halves n and takes its last bit as a leaf, so the calls form one chain, where fib(n) branches into two full subtrees. Properties shows one number's bits, its runs, its density of 1s and its two's complement.

Measured against the Zeckendorf register

The register model page holds the figures. Binary needs fewer digits for a given number of levels, 8 for 144 levels against 10, and its additions reach normal form in fewer rewrite steps and fewer normalization rounds: over every sum of two values below 144, 2.80 rewrite steps and 2.08 rounds on average against 4.17 and 2.73. The Zeckendorf register's quantization levels have the lower Hamming weight, so its multiply–accumulate takes fewer additions, and only it detects single-bit flips.
