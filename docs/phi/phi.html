Zeckendorf register

A register whose digits weigh 1, 2, 3, 5, 8, …, the Fibonacci numbers from 1 and 2, and whose normal form holds no two adjacent 1s, which makes it the Zeckendorf representation of its value. phi_prune.register models it beside a binary register, and the register model page measures the two.

  • One identity, two rules.F(k) + F(k+1) = F(k+2) gives the adjacent 1s rule, which merges two adjacent 1s upward. Applied to a doubled digit it gives the removal of 2 digits, 2F(k) = F(k+1) + F(k−2), which sends one carry up and one down.
  • Any order.Each rule keeps the value and touches at most three nearby digits, so the rules can fire in any order and every order ends at the same normal form.
  • What the code holds.Non-negative values only: from_int refuses a negative one, and the module has no borrow, comparison or division. The component's subtraction is the page's own.

The component below has three tabs. Arithmetic writes two numbers in the register, adds them digit by digit, or subtracts them, and replays each rule it fires until the register is in normal form. Its adjacent 1s rule and removal of 2 digits are merge and split in phi_prune.register, with the same cases at the bottom, 2 + 2 = 3 + 1 and 1 + 1 = 2, and the component fires one rule at a time, the removal of 2 digits before the adjacent 1s rule, where the module's normalize fires the lowest position first. Since both rule sets are confluent, the two reach the same normal form. Its borrow rule, F(k) = F(k−1) + F(k−2) read downward, has no counterpart in the code. Tree draws the call tree of the naive recursive fib(n), with fib(0) = 0 and fib(1) = 1, so it has fib(n + 1) leaves, fib(n) of them returning 1. Properties counts the valid patterns of a few cells, shows Fibonacci codewords and their comma, and compares how many values each cell adds in the two kinds of register.

What the code does with it

  • Quantization levels. FibonacciEncoder(n_digits) quantizes to the F(n_digits + 2) integers whose Zeckendorf representations fit in n_digits digits, every integer from 0 to F(n_digits + 2) − 1, and to_codeword writes a level's digits, which from_int matches on all 144 levels of 10 digits.
  • Addition. pour adds two registers digit by digit with no carries, and normalize or normalize_rounds fires the rules until no digit is 2 or more and no two adjacent digits are both 1. The same scan that finds no rule left to fire is the register's completion signal.
  • Multiply–accumulate. dot multiplies an activation by a weight level by adding the Fibonacci multiples of the activation for each 1 digit of the level, so a level's Hamming weight is its count of additions.
  • Single-bit errors. flip_detected reads a register with two adjacent 1s as corrupt, and correction_candidates lists the registers in normal form a single change from 1 to 0 away. Normalization keeps a corrupted value, so the check comes before it.
  • Fibonacci coding. phi_prune.gaps.fib_code appends a 1 to the Zeckendorf representation of n, and the Fibonacci codes page follows the codewords into the bitstream and the .phid file.

The dual register that pairs this one with the Fibonacci Q-matrix for powers is not in the code: git grep over phi's Python finds no matrix power, fast doubling, borrow or division. The Fibonacci Q-matrix and Computing F(n) pages show that mathematics as mathematics.
