phi · p4 · Zeckendorf

One matrix, M = [[1,1],[1,0]], runs the whole store

Nest stores with a p4 = 1 and a .claude = 0. Never put a p4 directly in a p4. The rules that are left are exactly the Fibonacci Q matrix. The same matrix numbers the model nodes, prunes them, and routes a task to one of them.

There is no quantum part. The Q in “Q matrix” is Charles King’s 1960 name for M. Nothing in phi or p4 runs on qubits. The only quantum link in phi is a citation in .docs/phi/Q.md to Q-matrix key generation (Lai et al., 2017).

1 · the nesting rule is the matrix

Two states, three moves, one forbidden

→ 0→ 1 from 011 from 110

Count the allowed moves between the two states and you get M. The 0 is the forbidden p4-in-p4.

Powers of M count the paths: Mn = [[F(n+1), F(n)], [F(n), F(n−1)]]. So the number of legal stores of each depth is a Fibonacci number. The 11 the store never makes also works as the comma in a stream of addresses: no length field and no lookup table needed.

3 · the model tree at k = 4

Four nodes, oldest history deepest

the owner’s reading
1101 100110001

The 4 nodes as the 4 cells of [[n1, n2], [n3, n4]]. Untested: k = 2, 3, 5 and 6 would show whether the k = 4 win comes from this shape or from the shard size.

A node’s parent is its address with the last p4 and the .claude’s before it removed (phi_rank.tree.parent), so the first four addresses all hang off the root. Leaves start from scratch: a node is 213 rows and the shared base 215, so the base doesn’t fit. Each node is pruned by phi_mask, which never keeps two adjacent rows. That is the same no-11 rule, applied to the weights.
